# SmartQA Pro - 经典信息检索指标评估报告

> 本报告详细介绍 RAG 系统中经典信息检索（IR）评估指标，供面试准备和系统优化参考。

---

## 一、指标概览

| 指标 | 英文名 | 中文名 | 理想值 | 适用场景 |
|------|--------|--------|--------|----------|
| **Precision@K** | Precision at K | 精确率@K | 1.0 | 检索结果质量 |
| **Recall@K** | Recall at K | 召回率@K | 1.0 | 检索完整性 |
| **MRR** | Mean Reciprocal Rank | 平均倒数排名 | 1.0 | 首条结果质量 |
| **NDCG@K** | Normalized DCG | 归一化折扣累积收益 | 1.0 | 排序质量（金标准） |
| **F1@K** | F1 Score at K | F1分数@K | 1.0 | P/R平衡 |
| **BM25** | Best Matching 25 | BM25算法 | N/A | 关键词检索 |

## 二、详细指标说明

### 2.1 Precision@K（精确率@K）

#### 是什么
在检索系统返回的前 K 个结果中，有多少是真正相关的文档。

#### 为什么用
- 衡量检索结果的质量
- 用户通常只关注前 K 个结果（如搜索第一页的 10 条）
- 反映"检索回来的东西对不对"

#### 如何计算

```
Precision@K = (前K个结果中相关文档数) / K
```

#### 理想值
**1.0** — 所有检索回来的都是相关的

#### 示例（面试可直接用）

```
查询: "公司IT服务台电话"
检索结果 Top-5: [doc_服务台位置, doc_VPN设置, doc_服务台流程, doc_IT部门, doc_会议室预订]
相关文档: [doc_服务台流程, doc_IT部门]

K=3 时的 Precision@3:
前3个结果中有1个相关 → Precision@3 = 1/3 = 0.333

K=5 时的 Precision@5:
前5个结果中有2个相关 → Precision@5 = 2/5 = 0.400
```

#### 面试回答模板

> "Precision@K 衡量的是检索结果前K项中相关文档的比例。
> 公式是：相关文档数 / K。
> 例如 K=5 时，如果返回的5个结果中有3个相关，Precision@5 = 0.6。
> 在 RAG 系统中，Precision@K 反映的是检索回来的上下文片段有多少是真正有用的。"

---

### 2.2 Recall@K（召回率@K）

#### 是什么
在所有相关文档中，有多少被检索系统找回来了。

#### 为什么用
- 衡量检索系统的覆盖率
- 反映"能找到多少相关的东西"
- 在需要全面信息的场景（如法律检索、医疗检索）尤为重要

#### 如何计算

```
Recall@K = (前K个结果中相关文档数) / (所有相关文档数)
```

#### 理想值
**1.0** — 所有相关文档都被检索到

#### 示例（面试可直接用）

```
知识库中共有 5 个相关文档: [A, B, C, D, E]
用户查询: "VPN配置方法"
RAG系统检索 Top-10 返回: [A, X, B, Y, C, Z, D, W, E, V]

Recall@5: 前5个中有 [A, B, C]，3个相关 → Recall@5 = 3/5 = 0.600
Recall@10: 前10个中有 [A, B, C, D, E]，5个相关 → Recall@10 = 5/5 = 1.000
```

#### 面试回答模板

> "Recall@K 衡量的是所有相关文档中有多少在前K个结果中被找到。
> 公式是：前K个相关文档数 / 总相关文档数。
> 例如总共有10个相关文档，前K=20个结果中有8个相关，Recall@20 = 0.8。
> **Precision 和 Recall 的区别**：Precision 是'检索回来的对不对'，
> Recall 是'对的东西找回来了多少'。两者通常呈跷跷板关系。"

---

### 2.3 MRR（Mean Reciprocal Rank，平均倒数排名）

#### 是什么
多个查询中，第一个相关文档出现位置的倒数的平均值。

#### 为什么用
- 特别适合"首条结果质量"很重要的场景
- 搜索引擎的"第一条命中"至关重要
- 对检索系统排序是否把正确答案放在前面很敏感

#### 如何计算

```
MRR = (1/Q) * Σ(1/rank_i)

其中 rank_i 是第 i 个查询第一个相关文档出现的位置（排名）
```

#### 理想值
**1.0** — 所有查询的第一个结果都是相关的

#### 示例（面试可直接用）

```
3个查询的检索结果评估：

查询1: [doc_A✗, doc_B✓, doc_C✗, doc_D✗]
       → 第一个相关文档是 doc_B，排名第2位 → RR = 1/2

查询2: [doc_E✓, doc_F✗, doc_G✗, doc_H✗]
       → 第一个相关文档是 doc_E，排名第1位 → RR = 1/1

查询3: [doc_I✗, doc_J✗, doc_K✗, doc_L✗]
       → 没有相关文档 → RR = 0

MRR = (1/2 + 1/1 + 0) / 3 = (0.5 + 1 + 0) / 3 = 0.5
```

#### 面试回答模板

> "MRR 关注的是正确答案的平均排名位置。对每个查询，找到第一个相关文档的排名，取倒数，然后平均。
> 例如三个查询的第一个相关文档分别排在第1、2、5位，MRR = (1/1 + 1/2 + 1/5) / 3 = 0.57。
> MRR 的特点是**只关心第一个正确答案**，不关心后面有多少。
> 这在搜索场景中很实用，因为大多数用户只点第一条结果。"

### 2.4 NDCG@K（Normalized Discounted Cumulative Gain）

#### 是什么
归一化折扣累积收益。考虑文档相关性程度和位置因素的评估指标，是搜索系统评估的**金标准**。

#### 为什么用
- 考虑文档相关性的不同程度（不只是二元相关，可以是 0-3 分的相关性等级）
- 对排名靠前的错误惩罚更重
- 是 Google、百度等搜索引擎评估的核心指标

#### 如何计算

```
DCG@K = Σ(i=1 to K) rel_i / log2(i+1)
IDCG@K = 按最优顺序排列的 DCG@K（所有相关文档排在最前面）
NDCG@K = DCG@K / IDCG@K
```

其中 rel_i 是第 i 个文档的相关性得分（通常 0=不相关, 1=相关, 2=高度相关, 3=完全匹配）

#### 理想值
**1.0** — 检索结果完美排序（最相关的永远排第一）

#### 示例（面试可直接用）

```
查询: "如何配置VPN"
检索结果 (Top-4): [A(高度相关), B(不相关), C(相关), D(不相关)]
相关性分数: [3, 0, 2, 0]  # 3=高度相关, 2=相关, 0=不相关

DCG = 3/log2(2) + 0/log2(3) + 2/log2(4) + 0/log2(5)
    = 3/1 + 0/1.58 + 2/2 + 0/2.32
    = 3 + 0 + 1 + 0 = 4.0

IDCG = 按最优排序: [3, 2, 0, 0]
IDCG = 3/log2(2) + 2/log2(3) + 0/log2(4) + 0/log2(5)
     = 3 + 1.26 + 0 + 0 = 4.26

NDCG = DCG / IDCG = 4.0 / 4.26 ≈ 0.94
```

#### 面试回答模板

> "NDCG@K 是搜索系统最常用的评估指标。相比 Precision@K，它有两个核心优势：
> 一是支持多级相关性（不只是相关/不相关，可以是0-3分的相关性等级）；
> 二是考虑位置折扣，排在第3名的错误比第10名更严重，因为 log2(3) < log2(10)。
> 公式上：NDCG = DCG / IDCG，其中 DCG 是实际排序的收益，IDCG 是理想排序的收益。
> 归一化后 NDCG 在 0-1 之间，1 表示完美排序。"

### 2.5 F1@K

#### 是什么
Precision@K 和 Recall@K 的调和平均，综合衡量两者。

#### 为什么用
- Precision 和 Recall 通常是跷跷板关系
- F1 综合考虑两者，找到平衡点
- 适合需要同时关注"准确"和"全面"的场景

#### 如何计算

```
F1@K = 2 * (Precision@K * Recall@K) / (Precision@K + Recall@K)
```

#### 理想值
**1.0** — Precision 和 Recall 都达到 1.0

#### 示例（面试可直接用）

```
场景: 知识库有 100 篇文档，其中 10 篇与查询相关

情况A（高 Precision）:
检索 Top-10 返回 8 篇，6 篇相关
P = 6/8 = 0.75, R = 6/10 = 0.60
F1 = 2*0.75*0.60/(0.75+0.60) = 0.667

情况B（高 Recall）:
检索 Top-20 返回 12 篇，8 篇相关
P = 8/20 = 0.40, R = 8/10 = 0.80
F1 = 2*0.40*0.80/(0.40+0.80) = 0.533

情况C（平衡）:
检索 Top-10 返回 6 篇，5 篇相关
P = 5/10 = 0.50, R = 5/10 = 0.50
F1 = 2*0.50*0.50/(0.50+0.50) = 0.500
```

#### 面试回答模板

> "F1@K 是 Precision@K 和 Recall@K 的调和平均，综合反映检索系统的性能。
> 公式是：2 × P × R / (P + R)。当 P 和 R 差距很大时，F1 会被拉低。
> 例如 P=0.8, R=0.4，则 F1 = 2×0.8×0.4/(0.8+0.4) = 0.53。
> F1 分数适合在 P 和 R 都重要的场景使用。"

### 2.6 BM25（Best Matching 25）

#### 算法说明

BM25 是 1994 年提出的经典检索算法，至今仍是搜索引擎和 RAG 系统的核心算法之一。

**核心思想**：基于词频和文档频率的统计模型，但做了两个关键改进。

#### 改进一：词频饱和（TF Saturation）

```
TF-IDF: score 随着词频线性增长，没有上限
BM25:   score = TF / (TF + k1)  →  边际收益递减
```

例如 k1=1.5 时：
| 词频 | TF-IDF 贡献 | BM25 贡献 |
|------|------------|----------|
| 1 | 1 | 0.40 |
| 3 | 3 | 0.67 |
| 10 | 10 | 0.87 |
| 100 | 100 | 0.99 |

#### 改进二：文档长度归一化

短文档包含查询词，更可能是精准匹配；长文档更可能包含大量无关内容。

```
BM25 归一化因子 = (1 - b + b × L_d / L_avg)

其中:
- L_d = 文档长度
- L_avg = 语料库平均文档长度
- b = 归一化参数（通常 0.75）
```

#### 完整公式

```
BM25(d, q) = Σ IDF(qi) × (TF(ti,d) × (k1 + 1)) / (TF(ti,d) + k1 × (1 - b + b × L_d / L_avg))
```

#### SmartQA 中的应用

我们使用 `rank_bm25` 库实现 BM25，作为**混合检索**的一部分：

```
Query → [向量检索 Top-20] + [BM25 Top-20] → 合并去重 → Reranker → Top-3
```

BM25 擅长精确关键词匹配（如"VPN"、"端口号"），向量检索擅长语义相似（如"网络连接问题"），两者互补。

#### 调参建议

| 参数 | 默认值 | 增大 → | 减小 → | 面试说什么 |
|------|--------|--------|--------|-----------|
| **k1** | 1.5 | 更重视词频差异 | 更忽略词频差异 | "k1控制词频的影响程度，增大k1会让词频高的文档得分更高" |
| **b** | 0.75 | 更惩罚长文档 | 更倾向长文档 | "b控制文档长度归一化，增大b会更多惩罚长文档" |

**实战建议**：
- 短文档为主（FAQ、条款）：增大 k1（如 2.0），减小 b（如 0.5）
- 长文档为主（文章、报告）：减小 k1（如 1.2），增大 b（如 0.9）
- 混合场景：保持默认 k1=1.5, b=0.75

#### 面试高频问题

**Q: BM25 和 TF-IDF 的区别？**

> "BM25 在 TF-IDF 基础上有两个核心改进：
> 一是 TF 饱和函数，使用 TF/(TF+k1) 替代简单的 TF，防止词频过高时过度加分；
> 二是文档长度归一化，使用 (1-b+b×L/avgL) 因子，更公平地比较不同长度的文档。"

**Q: BM25 和向量检索如何选择？**

> "BM25 擅长精确关键词匹配（如人名、术语、型号），向量检索擅长语义相似（如'网络连不上'匹配到'VPN配置问题'）。
> 两者互补，混合使用效果最佳。SmartQA 就是这样设计的——先用两种方法各召回 Top-20，合并去重后用 Reranker 精排。"

**Q: 什么时候 BM25 比向量检索更好？**

> "BM25 在以下场景表现更好：
> 1. 短查询（query 越短，向量表示越不准确）
> 2. 精确术语匹配（如产品型号、人名、专业术语）
> 3. 用户明确知道要找什么（搜索意图明确）
> 4. 查询和文档语言不一致的跨语言场景"

| 维度 | Precision@K | Recall@K | MRR | NDCG@K | F1@K |
|------|------------|----------|-----|--------|------|
| **关注点** | 检索质量 | 检索完整性 | 首条结果 | 排序质量 | 平衡性 |

## 四、SmartQA 中的实际应用

### 4.1 评估流程

```
TEST_QA_PAIRS (20题)
    ↓
RAG Agent 检索 → retrieved_contexts
    ↓
compute_ir_metrics_for_batch() → 批量计算指标
    ↓
生成 eval_ir_metrics_report.md
```

### 4.2 代码示例

```python
from test_ir_metrics import (
    precision_at_k, recall_at_k, mean_reciprocal_rank,
    ndcg_at_k, f1_at_k, compute_ir_metrics_for_batch
)

# 单查询评估
retrieved = ["chunk_1", "chunk_2", "chunk_3", "chunk_4", "chunk_5"]
relevant = ["chunk_1", "chunk_3"]

p = precision_at_k(retrieved, relevant, k=5)  # 2/5 = 0.4
r = recall_at_k(retrieved, relevant, k=5)      # 2/2 = 1.0
f1 = f1_at_k(retrieved, relevant, k=5)          # 0.57
n = ndcg_at_k(retrieved, relevant, k=5)        # ≈0.77

# 批量评估
summary = compute_ir_metrics_for_batch(
    retrieved_docs_list=[...],  # 多个查询的检索结果
    relevant_docs_list=[...],    # 多个查询的相关文档
    k=10
)
print(f"平均 Precision@10: {summary.avg_precision_at_k:.4f}")
print(f"平均 MRR: {summary.avg_mrr:.4f}")
print(f"平均 NDCG@10: {summary.avg_ndcg_at_k:.4f}")
```

### 4.3 评估结果解读

| 指标范围 | 含义 | 改进建议 |
|----------|------|----------|
| 0.9 - 1.0 | 优秀 | 保持现状 |
| 0.7 - 0.9 | 良好 | 可微调 |
| 0.5 - 0.7 | 一般 | 需优化检索策略 |
| < 0.5 | 较差 | 重新评估知识库或检索架构 |

## 五、面试速记卡

### Precision@K
```
Q: Precision@K 是什么？
A: 前K个结果中相关的比例 = 相关数 / K

Q: 什么时候 Precision 比 Recall 重要？
A: 当检索回来的内容质量比数量更重要时。
   例如用户只想确认一个事实，高 Precision 表示回来的都是对的。
```

### Recall@K
```
Q: Recall@K 是什么？
A: 所有相关文档中找到了多少 = K中相关 / 总相关

Q: 什么时候 Recall 比 Precision 重要？
A: 当不能漏掉相关信息时。
   例如法律检索、医疗诊断，漏掉重要文档后果严重。
```

### MRR
```
Q: MRR 是什么？
A: 第一个相关文档排名的倒数的平均值 = avg(1/rank)

Q: MRR 的局限？
A: 只看第一个正确答案，不关心后面有多少。
   适合"用户只点第一条"的场景，不适合需要全面结果的情况。
```

### NDCG@K
```
Q: NDCG@K 是什么？
A: 折扣累积收益的归一化值 = DCG / IDCG

Q: NDCG 为什么是搜索金标准？
A: 1) 支持多级相关性 2) 位置折扣（排名靠前错误更严重）3) 归一化后可比

Q: DCG 的折扣是什么意思？
A: 第i位的收益是 rel_i / log2(i+1)。
   排在第1位得1分，第2位得0.63分(i=2, log2(3)≈1.58, 1/1.58≈0.63)，第10位得0.3分。
   说明越靠后贡献越小。
```

### BM25
```
Q: BM25 两个核心改进是什么？
A: 1) TF饱和：TF/(TF+k1) 防止词频无限增长
   2) 长度归一化：(1-b+b×L/avgL) 公平比较不同长度文档

Q: k1 和 b 分别控制什么？
A: k1 控制词频影响程度（越大越看重词频）
   b 控制文档长度惩罚（越大越惩罚长文档）
```
