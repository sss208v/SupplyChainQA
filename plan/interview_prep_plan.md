# 面试话术演练规划

## 一、目标
让面试官在 10-15 分钟内理解项目价值，20 分钟追问后仍然认可技术深度。

## 二、演练流程（三阶段）

### 阶段 A：演示 Demo（5-8 分钟）
按 DEMO_SCRIPT.md 的 20 个 Query 筛选 5 个核心场景：
1. **知识库问答**（Query 1）— 展示 RAG 链路 + 引用溯源
2. **工具调用**（Query 3-4）— 展示 ReAct 循环（查库存/查订单）
3. **HyDE + 子问题**（Query 13-14）— 展示查询理解
4. **一键导入**（Query 19）— 展示 PDF 解析 + 批量入库
5. **RAGAS 评估**（Query 20）— 展示量化指标

**成果**：面试官看到产品效果+数据规模+评估指标

### 阶段 B：架构问答（8-10 分钟）
针对项目亮点准备 8 个高频问题，每个问题准备"一句话结论 + 展开"：

| # | 问题 | 一句话结论 |
|---|------|----------|
| 1 | 三种 Agent 模式的区别？ | ReAct 可控、LangChain 生态、LangGraph 前沿 |
| 2 | RAG 检索怎么做的？ | 向量+BM25 混合 → RRF 融合 → Reranker 精排 |
| 3 | 行级权限怎么实现的？ | Milvus ARRAY 字段 + array_contains 过滤 |
| 4 | PDF 表格怎么解析？ | pymupdf4llm → opendataloader → pdfplumber 三层回退 |
| 5 | RAGAS 指标怎么算的？ | CP 基于 rerank_score、Faith 基于关键词覆盖 |
| 6 | 为什么 CP=0.906？ | 小知识库（1034 chunks），混合检索架构有效 |
| 7 | 没有 LLM 生成也能评估？ | 仅检索模式评估检索质量，生成模式需另接 LLM |
| 8 | 最难的 Bug？ | LangGraph astream 事件结构误解 → final_answer 永远为空 |

### 阶段 C：深挖追问（5-10 分钟）
准备 4 个可能的追问，展示技术深度：

| 追问 | 应对策略 |
|------|----------|
| 为什么不用 LangChain 内置工具？ | TOOL_REGISTRY 复用现有架构，ainvoke 语义更清晰 |
| SSE 断连怎么办？ | Redis chat_memory 保存上下文，重连后拉取历史 |
| Reranker CPU 太慢怎么办？ | GPU 部署或 Query Cache 兜底，面试话术"知道局限" |
| 评估指标为什么不用 RAGAS 官方库？ | 自实现更可控，理解了原理而非调包 |

## 三、执行计划

1. **准备阶段**：确认前后端运行，启动 Docker+uvicorn+vite
2. **实测阶段**：逐一走过 5 个核心场景，记录各场景耗时、返回内容、可能翻车点
3. **话术整理**：针对实测结果写出应答话术，标注"一定要说的"和"小心别说的"
4. **追问训练**：模拟面试官角度，对每个技术点追问 2-3 层

## 四、产出物
- 实测各场景的预期耗时和返回样本
- 8 个高频问题的标准话术
- 4 个深挖追问的应答策略
- 一个"翻车应急"清单（如果演示时某功能挂了怎么说）
