# 检索融合增强 — OpenSpec 需求规格

> 版本: 1.0 | 日期: 2026-05-14

---

## 1. 现状

`rag_engine.py:_merge_results()` 只做了 RRF 等权融合 + chunk_id 去重。
面试时会被追问：重复内容怎么处理？两路检索结果矛盾怎么办？低质量结果怎么拦截？

## 2. 需求

### REQ-1：语义去重 [P0]

**问题：** 同一段落被切成相邻两个 chunk，内容高度重叠，RRF 融合后两段都进 Top-K。

**方案：** RRF 排序后，对相邻结果做 Jaccard 相似度检测，相似度 > 0.7 的只保留分数高的。

**验收：**
- [ ] 相邻 chunk 做 2-gram Jaccard 去重
- [ ] 阈值 0.7，保留 rrf_score 高的
- [ ] 不影响 chunk_id 不同的正常结果

### REQ-2：最低相关性阈值 [P0]

**问题：** RRF 分数很低的 chunk（两路都没排进前面）也会被返回，LLM 看到噪音。

**方案：** RRF 分数 < 0.01 的结果直接丢弃（相当于两路都在 40+ 名开外）。

**验收：**
- [ ] RRF 分低于阈值的 chunk 不进入最终结果
- [ ] 可配置阈值

### REQ-3：多源冲突检测 [P1]

**问题：** 两个 chunk 对同一事实给出矛盾信息时（如"安全库存=50" vs "安全库存=100"），系统静默合并。

**方案：** 对 Top-5 结果做实体-数值对提取，发现同一实体的数值冲突时，在 context 中标注。

**验收：**
- [ ] 提取 chunk 中的"实体名 + 数字"对
- [ ] 同一实体出现不同数值时，标记为冲突
- [ ] 冲突信息追加到 context 末尾供 LLM 判断

### REQ-4：自适应 RRF 权重 [P2]

**问题：** 精确查询（如"MAT-001库存"）应该加重 BM25 权重，语义查询（如"怎么处理"）应加重向量权重。

**方案：** 根据 query 复杂度分析结果动态调整 RRF 权重。

**验收：**
- [ ] 精确查询：BM25 权重 ×1.5
- [ ] 语义查询：向量权重 ×1.5
- [ ] 默认查询：等权

---

## 3. 实施

### Step 1：增强 `_merge_results()`（30行）
- 加 RRF 最低分阈值
- 加相邻 chunk Jaccard 去重
- 加冲突检测并追加 context

### Step 2：冲突检测独立函数
- `_detect_conflicts(chunks)` → list of conflict markers

### Step 3：更新 `search()` 调用链
- 传递 query_type 用于自适应权重

---

## 4. 验收

```
[ ] 相似 chunk 去重生效（Jaccard > 0.7 只保留一个）
[ ] 低分结果过滤（RRF < 0.01 丢弃）
[ ] 冲突检测标记追加到 context
[ ] 面试话术："融合后还会做三层后处理——语义去重、最低分过滤、数值冲突检测"
```
